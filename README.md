# 현담토목 업무관리

토목·구조용 콘크리트 2차제품(흄관·맨홀·측구·옹벽블록 등)을 생산·판매하는 **현담토목**의 업무 관리 프로그램과, 수주(영업) 전략 문서를 한곳에 모은 저장소입니다.

| 구분 | 위치 | 내용 |
|---|---|---|
| **업무관리 프로그램** | 이 저장소 전체 (`src/`, `deploy/` …) | 견적·매출·입금·매입·재고·생산일보·배차·출고·관급 발주·AI 비서까지 한 화면에서. 브라우저와 휴대폰에서 씁니다 |
| **수주 전략 문서** | `marketing/` | 1인 운영 기준의 마케팅 재분석, 60일 실행표. 브라우저에서 바로 열립니다 (아래 「수주 전략 문서」) |

프로그램은 같은 업종의 **현담토목 업무관리** 프로그램(`kimhyeondam/pr-practice-calculator`)을 그대로 가져와 회사 이름·지역(전북)·기본 규격표·아이콘을 현담토목용으로 바꾼 것입니다. 기능은 두 프로그램이 같으며, 앞으로는 이 저장소에서 따로 발전시킵니다.

## 프로그램이 마케팅 문서의 「다섯 접점」을 어떻게 받쳐 주나

`marketing/03-혼자하는-수주.html` 은 마케팅을 따로 하지 않고, 매일 하는 업무 다섯 가지에 1~3분짜리 동작을 붙이자고 합니다. 프로그램에서 그 자리는 다음과 같습니다.

| 접점 | 문서가 말하는 동작 | 프로그램에서 하는 곳 |
|---|---|---|
| 견적 낼 때 | 같이 들어가는 품목 한 줄, 운반비 분리, 하단 고정 문구 3줄 | **재무 → 견적관리**: 품목 검색으로 흄관·맨홀·부속자재를 함께 넣고, 운반비를 별도 줄로. 견적서 PDF 하단 문구는 **시스템 설정**의 회사 정보·계좌와 함께 찍힙니다 |
| 출고할 때 | 명세서 하단 한 줄, 기사에게 "다음 현장 어디?", 상차 사진 1장 | **배차·출고**: 기사 링크로 사진 올리기, 거래명세표 자동 발행. 기사에게 들은 현장 정보는 **영업 → 리드관리**에 한 줄 |
| 입고할 때 | 공급사 영업에게 "요즘 어디가 바쁘대요?" | **매입관리**(원자재 입고) 메모란과 **리드관리** |
| 세금계산서 발행할 때 | 월 1회, 모든 거래처에 A4 1장 동봉 | **매출관리 → 엔택스로 복사**로 계산서 전표를 만들고, **메일관리**로 거래처에 한꺼번에 발송 |
| 회계 마감할 때 | 거래처별 전년 동월 대비 30% 이상 빠진 곳 찾기 → 다음 날 전화 1통 | **월간 보고**(거래처별 매출·미수금)와 **현담비서** 브리핑. 전화할 거래처는 **할일관리**에 등록 |

## 실행 방법

```bash
npm install     # 처음 한 번만
npm run dev     # 개발 서버 실행 후 http://localhost:3000 접속
```

운영용으로 띄울 때는 `npm run build` 뒤 `npm run start` 를 씁니다.

## 첫 계정

| 계정 | 비밀번호 | 역할 |
|------|----------|------|
| admin | 서버 설정 `ADMIN_PASSWORD` 값 (내 컴퓨터에서 `.env.local` 없이 실행하면 `hyundam1234`) | 관리자 |

처음 실행할 때 관리자 계정 하나만 만들어지고, 예시 자료는 들어가지 않습니다(`FRESH_START=1` 기본).
직원 계정은 관리자 메뉴 **직원관리**에서 추가합니다. 비밀번호는 암호화(scrypt)되어 저장됩니다.

화면 모양을 예시 자료로 먼저 보고 싶으면 `.env.local` 에 `FRESH_START=0` 을 넣고 실행합니다. 이때는 예시 직원 `staff1 ~ staff5`(비밀번호 `hyundam1234`)도 함께 만들어지며, 나중에 **시스템 설정 → 예시 데이터 지우기**로 정리할 수 있습니다.

## 환경 변수 (.env.local)

`.env.example`을 복사해 `.env.local`을 만들고 값을 채웁니다. 실제 운영 시에는 반드시 바꿔야 합니다.

| 변수 | 설명 |
|------|------|
| `AUTH_SECRET` | 로그인 출입증(쿠키)에 서명하는 비밀키. 길고 복잡하게 |
| `ADMIN_ID`, `ADMIN_PASSWORD` | 첫 실행 시 만들어지는 관리자 계정 |
| `ANTHROPIC_API_KEY` | AI 비서를 Claude에 연결할 때. 없으면 내장 비서가 동작 |
| `DATABASE_URL` | PostgreSQL 주소. 없으면 서버의 `data/` 폴더에 파일로 저장 |
| `DATA_DIR` | 파일 저장 폴더를 바꾸고 싶을 때만 (기본 `./data`) |

## 데이터 저장에 대해

입력한 내용은 **서버 저장소**에 저장되어 모든 직원이 같은 데이터를 봅니다.

| 방식 | 설정 | 언제 쓰나 |
|------|------|-----------|
| 파일 저장 (기본) | 없음. `data/` 폴더에 `tasks.json` 같은 파일로 저장 | 회사 PC나 작은 서버 한 대에서 쓸 때 |
| PostgreSQL | `DATABASE_URL=postgres://...` | Vercel처럼 파일을 남길 수 없는 곳, 또는 안정적인 백업이 필요할 때 (Supabase·Neon 무료 요금제로 시작 가능) |

- 컬렉션(할일·일정·프로젝트·고객·리드·견적·매출·입금·자료실·AI 사용량·직원)마다 JSON 하나로 저장하는 단순한 구조입니다.
- 예전에 브라우저에 임시 저장돼 있던 내용은 처음 접속할 때 자동으로 서버에 올라갑니다.
- 같은 화면을 두 사람이 동시에 고치면 나중에 저장한 쪽이 남습니다. 소규모 회사 기준으로는 충분하며, 필요해지면 항목 단위 저장으로 바꿀 수 있습니다.
- `data/` 폴더는 Git에 올라가지 않습니다. 정기적으로 백업하세요.

## AI 비서(현담비서)

- 오른쪽 아래 ✦ 버튼을 누르면 채팅 창이 열립니다. 할일·일정·프로젝트·고객·견적·매출·입금 현황을 물어볼 수 있습니다.
- **API 키가 없으면 "내장 비서"** 가 정해진 질문(브리핑, 지연 할일, 일정, 미수금, 매출, 매입·미지급금, 견적, 프로젝트, 리드, 고객, 고객 이름 질문)을 프로그램 안에서 계산해 답합니다.
- `ANTHROPIC_API_KEY`를 넣으면 **Claude(claude-sonnet-5)** 가 자유로운 질문에도 답합니다. (명함·납품 문서 인식과 회의록 정리는 정확도를 위해 claude-opus-5 를 씁니다.) 연결에 실패하면 자동으로 내장 비서가 대신 답합니다.
- 관리자 메뉴 **현담비서 사용량**에서 질문 횟수, 질문자, 토큰, 예상 비용을 봅니다.
- **명함관리 → 📷 사진으로 추가**: 명함 사진을 올리면 Claude가 이름·회사·직책·전화·이메일·주소를 읽어 바로 저장합니다(API 키 필요). 휴대폰에서는 카메라가 바로 열립니다.

## 스마트 업로드 (사진 한 장으로 등록)

대시보드 맨 위의 점선 상자에 사진이나 PDF를 끌어다 놓거나(휴대폰은 눌러서 카메라로 촬영), 현담비서 창의 📎 버튼으로 올리면 AI가 어떤 서류인지 판별하고 값을 읽어 확인 창을 띄웁니다. 종류가 틀리면 버튼으로 바꿀 수 있고, 「○○관리에 저장」을 누르면 그 메뉴에 들어갑니다.

| 서류 | 저장되는 곳 |
|------|-------------|
| 명함 | 명함관리 |
| 우리 회사가 공급자인 거래명세표 | 매출관리 (품목·금액 포함) |
| 매입 명세표·영수증·세금계산서 | 매입관리 (공급가액·부가세) |
| 분할납품요구서·납품요구서 | 프로젝트관리 (기존 프로젝트 추천·중복 감지) |
| 입금 확인증·통장 내역 | 입금관리 |
| 회의·행사·납품 통지 | 일정관리 |
| 지시·요청 메모 | 할일관리 |

**대리점 납품(다른 회사가 우리 제품을 직접 납품한 송장)**: 고객관리에서 거래처에 「대리점」을 체크해 두면, 그 대리점이 공급자로 적힌 거래송장·명세표 사진을 올렸을 때 사업자번호(또는 상호)로 알아보고 **매출을 대리점 앞으로** 잡습니다. 최종 납품처(공사 회사·현장·담당 연락처)는 매출 메모에 남습니다. 등록되지 않은 공급자면 "대리점으로 등록할까요?"라고 물어보고 체크 한 번으로 고객관리에 등록합니다. 송장에 단가가 없으면 같은 대리점에 판 같은 품목의 이전 단가를 자동으로 채우고, 그래도 없으면 매출관리에 「단가 미입력」으로 표시됩니다.

- 서버 코드: `src/app/api/inbox/analyze` (AI 판별·추출, claude-opus-5), `src/lib/inbox/resolveParties.ts` (사업자번호로 매출·매입·대리점 판정), `src/lib/inbox/mapping.ts` (각 메뉴 기록으로 변환), `src/components/inbox/SmartInbox.tsx` (화면)

## 매출과 거래명세표 (한 몸으로 움직임)

매출은 금액만 적는 게 아니라 **품목(품명·규격·단위·수량·단가)** 을 넣으면 공급가액·부가세·청구액이 자동으로 계산됩니다. 「등록 + 거래명세표 만들기」를 누르면 같은 내용의 거래명세표(ST-번호)가 양식 문서에 함께 만들어지고, 매출 화면에서 「PDF 보기」로 바로 볼 수 있습니다.

- 양식 문서에서 거래명세표를 먼저 만들어도 같은 내용의 매출이 자동 등록됩니다.
- 어느 쪽을 고쳐도(수량·단가·날짜·거래처) 다른 쪽이 같이 바뀝니다. 매출을 지우면 명세표도, 명세표를 지우면 매출도 함께 지워집니다.
- 선급금·정산 차액처럼 품목이 없는 청구는 「품목 없이 금액만 입력」을 켜고 적습니다.
- 프로젝트관리에 올린 납품요구서에서 바로 발행할 수도 있습니다: 프로젝트 → 납품 문서 → 「거래명세표 발행」 → 이번 차수 수량·단가 입력 → 거래명세표 + 매출이 함께 등록되고, 문서에는 품목별 납품/잔여 수량과 차수가 기록되며 프로젝트 누적 매출·진행률(납품 수량 ÷ 요구 수량)이 자동 갱신됩니다.
- 매출관리는 연도별(1~12월 탭) 보기와 최근 3·6·12개월 보기를 지원합니다.
- 규칙 코드: `src/lib/sales/revenueDoc.ts`, `src/lib/projects/orders.ts` (납품/잔여 수량)

## 납품 문서 올리기 (프로젝트관리)

## 메일관리 (네이버·지메일 연동)

- 네이버 메일은 공식 API가 없어 **IMAP(읽기)·SMTP(보내기)** 표준 방식으로 연동합니다. 지메일·다음·회사 메일 서버도 같은 방식으로 됩니다.
- 직원 준비: 네이버 메일 → 환경설정 → **POP3/IMAP 설정에서 IMAP 사용 켜기**. 2단계 인증을 쓰면 **애플리케이션 비밀번호**를 발급해 프로그램에 넣습니다.
- 계정 종류
  - **공용**: 직원 모두 열람·발송 가능. 담당자가 자리를 비워도 다른 직원이 거래명세표·견적서를 대신 보냅니다. 대신 보낸 메일은 본문 끝에 "(○○○ 발송)"이 붙고 **발송 기록**에 누가 보냈는지 남습니다.
  - **비공개**: 등록한 본인만 열람·발송 (대표 메일용). 관리자만 등록할 수 있습니다.
- 비밀번호는 `AUTH_SECRET`으로 만든 열쇠로 암호화해 저장하며 화면에 다시 표시하지 않습니다. `AUTH_SECRET`을 바꾸면 메일 계정을 다시 등록해야 합니다.
- 보낸 사람 주소가 고객·리드·명함의 이메일과 같으면 목록에 "고객 · ○○건설"처럼 표시됩니다.
- 첨부 파일은 합계 10MB까지 보낼 수 있습니다. 실제 네이버 서버 연결은 운영 환경에서 계정을 등록해 확인하세요(개발 환경에서는 가짜 메일 서버로 검사했습니다).

## 계약과 전자서명

- 관리자 메뉴 **계약 템플릿**에 `{{고객명}}` `{{계약금액}}` 같은 빈칸이 있는 틀을 두고, **계약관리**에서 고객·금액·기간·품목을 넣으면 본문이 자동 생성됩니다.
- "발송"을 누르면 서명 링크(`/sign/<token>`)가 만들어지고, 메일 계정이 연동돼 있으면 PDF와 함께 고객에게 발송됩니다.
- 고객은 로그인 없이 링크에서 내용을 확인하고 이름 입력 + 손글씨 서명으로 **서명완료** 처리하며, 서명 이미지와 시각·IP가 계약에 기록되고 PDF에 들어갑니다.
- 이 전자서명은 간이 방식입니다. 법적 효력이 중요한 큰 계약은 공인 전자서명 서비스나 서면 날인을 병행하세요.

## 생산일보 · 재고관리 · 직원출근부

- **생산일보**: 날짜·라인·작업 인원·품목별 계획/생산(양품)/불량·특이사항을 적습니다. 저장하면 양품 수량이 재고관리에 「생산입고」로 자동 들어가고, 일보를 고치거나 지우면 재고도 따라 바뀝니다. 재고관리에 없는 품명을 적으면 새 품목이 자동 등록됩니다.
- **재고관리**: 재고는 따로 저장하지 않고 입출고 내역의 합으로 계산합니다(기초재고 + 생산입고 − 출하 …). 매출관리나 프로젝트에서 거래명세표를 발행하면 품명·규격이 같은 품목이 「출하」로 빠집니다. 안전재고 이하는 빨간색으로 경고합니다. 반품·폐기·실사 조정만 손으로 넣습니다.
- **직원출근부**: 직원 × 날짜 표에서 칸을 톡 누르면 출근 → 휴가 → 결근 → 외근 → 빈칸 순으로 바뀝니다. 길게 누르면(PC는 오른쪽 클릭) 출퇴근 시간·연장근무·메모를 적습니다. 「오늘 전원 출근 처리」로 한 번에 기록한 뒤 예외만 고치면 빠릅니다. 직원 목록은 관리자 메뉴 「직원관리」를 따릅니다.
- 현담비서 브리핑에 오늘 생산량, 재고 부족 품목, 오늘 출근 인원이 함께 나옵니다.

## 배차·출고 · 원자재 · 품질 · 급여 · 단가표 · 월간 보고

- **배차·출고관리**: 매출관리의 「배차」 버튼(또는 직접 등록)으로 차량·기사·품목을 정하면 기사님용 링크(`/deliver/<token>`)가 생깁니다. 「문자로 보내기」(휴대폰 문자 앱), 「링크 복사」, QR, 「카드 이미지로 공유」(카카오톡 등)로 전달합니다. 기사님은 로그인 없이 상차 완료 → 출발 → 도착 → 인수 완료 버튼을 누르고 카메라로 사진(8장까지)을 올립니다. 사무실 화면은 30초마다 새로 읽습니다. 「차량·기사 관리」에 자차·용차를 등록해 두면 배차 때 고릅니다.
- **납품 사진 보관**: 기사님이 올린 사진은 `data/photos/dispatch/<배차id>/<사진id>.jpg` 파일로 저장되고 장부에는 경로만 남습니다. 사진은 로그인한 직원 또는 그 배차의 기사 링크(token)로만 볼 수 있습니다. 시스템 설정의 「납품 사진 보관 기간」(기본 3년)이 지난 배차의 사진은 하루 한 번 자동으로 지워지고 배차 기록에는 정리된 장수만 남습니다. 백업은 JSON을 매일 압축하고, 사진은 새 파일만 `backups/photos/`에 한 벌 복사합니다(복원할 때 `data/photos/`로 되돌려 넣으면 됩니다).
- **원자재 재고**: 시멘트(ton)·골재/자갈(㎥)·혼화재(kg)·수로관 철망(EA). 매입관리에 품목명이 자재와 맞는 매입을 넣으면 「매입입고」, 생산일보를 저장하면 재고관리 품목의 「배합」(1개당 자재량)대로 「생산사용」이 자동으로 빠집니다. 배합은 재고관리 → 품목 수정에서 넣습니다.
- **품질관리**: 시험일·타설일·배치번호·품목·시험항목·재령·공시체 측정값·기준값·판정·시험자·검토자·성적서 번호·첨부(PDF/사진). 회사 자체 시험성적서 양식을 받으면 그 양식대로 칸과 인쇄를 맞출 예정입니다.
- **급여 집계** (관리자): 직원별 급여 기준(월급/일급/시급, 연장 시급·배율, 고정 수당·공제)을 넣으면 출근부의 출근일·연장시간으로 월 집계표를 만듭니다. 연장수당 = 시간 × 시급 × 배율(1.5), 시급은 월급÷209 또는 일급÷8. 월급제 결근은 월급÷기준일수(22)만큼 공제. 인쇄/PDF 저장 가능. 4대보험·세금은 계산하지 않습니다.
- **단가표**: 품목 기준 단가 × 거래처 적용률(%) = 매출 단가. 매출 등록에서 거래처·품명을 넣고 칸을 벗어나면 단가·단위가 자동으로 들어가고, 「단가표로 채우기」로 전체를 다시 계산할 수 있습니다. 거래처별 단가표 탭에서 거래처를 고르면 전체 품목 단가가 나오고 인쇄됩니다.
- **수금 안내**: 매출관리에서 미입금·부분입금 건의 「수금 안내」를 누르면 정중/보통/강경 세 가지 문안이 만들어지고, 문자·메일 앱으로 바로 보내거나 복사합니다. 입금 계좌는 시스템 설정의 계좌를 씁니다.
- **월간 보고**: 달을 고르면 매출·입금·매입·차액·미수금·미지급·생산·불량률·출하·배차·재고 부족·품질·출근을 한 장으로 보여 주고, 전월 대비 증감과 거래처별 매출, 미수금 상위, 품목별 생산을 함께 냅니다. 「인쇄 / PDF 저장」으로 뽑습니다.

## 관급 발주 현황 (나라장터 연동)

- 「영업 → 관급 발주」에서 나라장터(조달청)에 올라온 **전북 지자체 입찰공고**(공사·물품·용역)를 지역별·발주 방식별로 봅니다. (지역은 `BID_REGION` 으로 바꿀 수 있습니다: jb 전북 (기본), gj 광주·전남)
- 지역 묶음(전북): 전북도청·6개 시(전주·군산·익산·정읍·남원·김제)·8개 군(완주·진안·무주·장수·임실·순창·고창·부안), 교육청, 공사·공단, 기타. 수요기관 이름으로 자동 분류합니다(`src/lib/bids/classify.ts`).
- 발주 방식: 계약방법 원문을 수의계약·제한경쟁·일반경쟁·지명경쟁으로 묶어 지역 카드에 막대로 보여 주고 「주로 ○○」를 표시합니다.
- 「우리 제품 관련」: 공고명에 흄관·맨홀·경계석·블록·수로관·배수로 같은 키워드가 있으면 ★ 표시. 기본은 관련 공고만 보이고, 체크를 풀면 전부 보입니다.
- 「리드로」를 누르면 리드관리에 유입경로 「입찰공고」로 등록됩니다(메모에 공고번호·마감·링크).
- 연결 방법: 공공데이터포털(data.go.kr) 회원가입 → 「조달청_나라장터 입찰공고정보서비스」 활용신청(무료, 즉시 승인) → 일반 인증키(Decoding)를 서버 `~/hyundam/.env.production` 에 `DATA_GO_KR_KEY=…` 로 넣고 `docker compose up -d` (내 컴퓨터는 `.env.local`).
- 화면을 열 때 6시간이 지났으면 자동으로 최근 7일치를 다시 가져오고, 버튼으로 최근 7·14·31일치를 바로 가져올 수 있습니다. 180일 지난 공고는 지웁니다. 저장 위치 `data/bids.json`.
- 인증키가 없으면 예시 공고 6건이 보이고, 실제 자료를 한 번 가져오면 사라집니다.

### 납품 현황 탭 (누가 어디에 무엇을 납품했나)

- 조달데이터허브(data.g2b.go.kr)의 「나라장터쇼핑몰 납품요구 물품 내역」 CSV 를 올리면 전북 수요기관 건만 골라 지역별(상위 업체 점유율 막대)·업체별(금액·비중·주요 품목·지역)·목록으로 정리합니다. 우리 회사(시스템 설정의 회사명)는 초록색으로 표시되고 「우리 회사 몫」 %가 나옵니다.

UTF-16·UTF-8·EUC-KR 과 탭·쉼표·세미콜론 구분을 자동으로 알아보고, 제목 줄(수요기관·업체명·품명이 있는 줄)을 찾아 그 아래만 읽습니다. 칸 이름은 「이런 글자가 들어간 칸」으로 찾습니다(`src/lib/bids/deliveries.ts` mapHeader). 같은 납품요구번호·물품순번의 변경 차수는 최신 것만 남깁니다. 브라우저가 한 줄씩 읽어 설정한 지역(전북) 것만 5,000건씩 서버에 보내므로 수십만 줄 파일도 됩니다. 엑셀(xlsx)은 CSV 로 저장해서 올려야 합니다.

- ② 발주계획: 각 기관이 연초에 올리는 「올해 발주 예정 목록」을 「조달청_나라장터 발주계획정보서비스」에서 등록일 기준 31일씩 잘라 가져와 설정한 지역(전북) 것만 발주 예정 달별로 보여 줍니다. 공고에 붙은 발주계획 번호(orderPlanUntyNo)로 「공고 나옴」 표시. 활용신청은 같은 인증키로 한 번 더 필요. 저장 `data/orderPlans.json`. 응답 항목 이름이 문서마다 달라 여러 이름을 함께 읽으며(`src/lib/bids/plans.ts` toPlan), 「연결 확인」이 첫 건의 원문 항목을 보여 주므로 이름이 다르면 거기서 확인해 고치면 됩니다. 요청 주소는 `G2B_PLAN_API_BASE` 로 바꿀 수 있습니다.

## 인수증 사진 (서명 받은 거래명세표)

- 스마트 업로드에 서명·도장이 있는 거래명세표 사진을 올리면 AI가 `signed`(서명 여부)·`docNo`(문서 번호)를 읽고, 확인 창에서 「이 사진을 인수증으로 보관」이 기본으로 켜집니다. 저장하면 매출에 사진이 붙습니다.
- 같은 명세표가 매출관리에 이미 있으면(문서 번호가 같거나, 거래처·날짜·금액이 같으면) 「그 매출에 인수증 사진만 붙이기」가 기본이라 매출이 두 번 잡히지 않습니다.
- 매출관리 각 줄의 「✍ 인수증 N」/「📷 인수증」 단추로 사진을 보고, 휴대폰 카메라로 바로 추가하거나 지웁니다. 크게 보기·내려받기 가능.
- 저장: 파일은 `data/photos/receipts/<매출id>/<사진id>.jpg`, 목록은 `receipts` 컬렉션(`src/lib/receipts.ts`). API `/api/revenues/receipt/[revenueId]` (POST 저장·DELETE 삭제), `/api/revenues/receipt/[revenueId]/[file]` (로그인한 직원만 사진 보기). 매일 백업에 포함.

## AI 비서 토큰 줄이기

- Claude 에게는 화면용 전체 현황(`buildSnapshot`)이 아니라 요약본(`slimSnapshot`)만 보냅니다: 목록마다 25건까지, 프로젝트의 납품요구서 품목·재고 0인 품목·긴 메모는 뺍니다. 품목 340종·프로젝트 문서까지 다 보내던 때는 질문 한 번에 약 5만 토큰이었고, 요약본은 2천~5천 토큰입니다.
- 사용량 화면은 입력 토큰 중 캐시 재사용분을 따로 보여 주고, 예상 비용은 캐시 재사용 10%·캐시 저장 125% 요금을 반영합니다. 같은 현황을 5분 안에 다시 물으면 대부분 캐시에서 읽습니다.
- 재고 부족 경고(`lowStock`)는 안전재고를 0보다 크게 정한 품목만 봅니다. 0은 「정하지 않음」입니다(카탈로그 품목 전체가 부족으로 뜨던 문제).

## 명함관리 담당자별 보관

- 명함마다 **담당자**(받은 직원)가 붙습니다(`BusinessCard.ownerId/ownerName`). 등록·사진 추가·스마트 업로드 때 로그인한 직원이 자동으로 담당자가 됩니다.
- **직원은 자기 담당 명함만** 봅니다. 서버(`/api/data/businessCards`)가 관리자가 아니면 본인 명함만 내려주고, 저장할 때도 본인 명함만 갈아 끼우며 담당자를 본인으로 고정하므로 화면을 우회해도 남의 명함을 볼 수 없습니다.
- **관리자는 전체**를 보고, 「전체 · 미지정 · 직원별」 탭으로 나눠 봅니다. 미지정 탭에서는 보이는 명함의 담당자를 한꺼번에 지정하고, 직원 탭에서는 그 직원의 명함을 다른 직원에게 통째로 넘길 수 있습니다(퇴사·인수인계). 명함 수정 창에서 담당자를 바꿀 수도 있습니다.
- 예전부터 있던 명함은 「미지정」이라 관리자만 보입니다. 미지정 탭에서 직원별로 나눠 주세요.

## 생산일보 빠르게 쓰기 (★ 생산 품목 · 어제 복사 · 양식 인쇄)

- **★ 생산 품목**: 재고관리 목록의 별표(☆/★)를 켜면 「우리 공장이 만드는 품목」이 됩니다(`Product.favorite`). 「생산 품목만」으로 걸러 볼 수 있고, 품목 수정 창에도 체크가 있습니다.
- **생산일보 작성**: ★ 품목이 카드로 쭉 나오고 생산·불량 수량만 칩니다. 비운 품목은 저장되지 않습니다. 「○/○ 일보 복사」는 가장 최근 일보의 품목·수량·인원·시간을 가져옵니다. ★에 없는 품목은 아래 「그 밖의 품목」 표에서 검색해 넣습니다.
- **양식 인쇄** (`/dashboard/production/print`): ★ 품목이 카탈로그 이름 그대로 박힌 종이 양식(A4)에 수량만 손으로 적고, 사진을 찍어 스마트 업로드에 올리면 이름이 정확히 같아 바로 연결됩니다. 날짜·빈 줄 수를 정해 인쇄합니다(`.doc-print-root`로 메뉴 없이 인쇄).

## 명함 QR 코드 · 회사 소개 페이지 (/company)

명함에 QR을 넣어 두면 휴대폰으로 찍는 즉시 **로그인 없이** 회사 소개 페이지가 열립니다. 주소는 `https://도메인/company` 하나이고, 프로그램 자료를 그대로 보여 줍니다.

- **공급원승인서**: 「시스템 설정 → 명함 QR 코드 · 회사 소개 페이지」에서 PDF를 올리면 누르는 즉시 내려받아집니다 (여러 건 가능).
- **카탈로그**: 같은 곳에서 올린 PDF를 「열기」(브라우저에서 보기) 또는 「저장」.
- **생산품목**: 재고관리의 품목 목록이 분류 → 품명 → 규격으로 자동으로 나옵니다 (끌 수 있음). 품목을 고치면 소개 페이지도 같이 바뀝니다.
- 상호·로고·전화·이메일·주소·사업자번호는 시스템 설정의 회사 정보를 씁니다. 전화는 눌러서 걸 수 있고 주소는 네이버 지도로 이어집니다.
- QR 그림은 설정 화면에서 **PNG**(카카오톡·문자용)와 **SVG**(명함 인쇄소용, 키워도 안 깨짐)로 내려받습니다. 현담토목 서버는 그 서버 주소로 QR이 만들어집니다.

화면 구성(2026-09 새 디자인, DESIGN.md 토큰만 사용): ① 머리글(로고·상호·전화) → ② 첫 화면(두 줄 제목, 한 줄 소개, 「공급원승인서 내려받기」검정 알약 버튼 + 「카탈로그 보기」, 제품 사진) → ③ 서류(한 줄씩 열기·저장) → ④ 생산품목(분류별 사진 타일 9개, 누르면 아래 규격 목록이 펼쳐짐) → ⑤ 연락처·공장 위치. 분류 사진은 `public/brand/products/`(카탈로그에서 추출), 휴대폰은 한 줄 배치이며 버튼이 화면 너비로 커집니다. 섹션이 살짝 떠오르는 움직임은 `globals.css`의 `.rise`이고, 「움직임 줄이기」 설정이면 꺼집니다. 첫 문장은 시스템 설정의 「한 줄 소개」가 있으면 그것을, 없으면 지역 이름이 들어간 기본 문장을 씁니다.

저장 위치: 파일 본체는 `data/public/`, 목록·한 줄 소개·품목 표시 여부는 `data/settings.json` 의 `publicPage` (둘 다 매일 백업에 포함). 내려받기 주소 `/api/public/files/파일` 은 누구나 열 수 있지만 목록에 있는 파일만 내려주고, 올리기·삭제(`/api/admin/public-files`)는 관리자만 됩니다. 파일은 PDF·PNG·JPG 20MB 이하.

## 속도와 화면 다듬기

- 화면 자료(`useServerState`)는 브라우저 임시 저장(sessionStorage, 10분)에 남겨 두었다가 다른 화면에 갔다 오면 먼저 그리고, 서버 답이 오면 바꿔 끼웁니다(첫 화면은 서버 렌더링과 같게 유지하기 위해 화면이 붙은 직후 읽음). 저장은 그대로 「서버 최신 값 위에 다시 적용」 방식이라 옛 자료를 덮어쓰지 않습니다.
- 서버는 공고(bids)·납품요구(deliveries)·대조 결과를 메모리에 한 번 읽어 두고 저장할 때만 다시 읽습니다.
- 메뉴 아이콘은 `src/components/MenuIcon.tsx` 의 선 아이콘(주소별 path), 카드 그림자·표 머리글·입력 칸 초점·얇은 스크롤바·불러오는 중 반짝임은 `globals.css` 에 있습니다.

## 화면 디자인 규칙 (DESIGN.md)

- 화면의 색·글꼴·둥글기·그림자는 저장소 맨 위 `DESIGN.md`(Vercel 스타일 설명서)의 토큰만 씁니다. 바탕 canvas-soft(#fafafa), 카드 canvas(#fff), 글씨 ink(#171717)/body(#4d4d4d)/mute(#888), 선 hairline(#ebebeb), 강조 ink 버튼(검정 알약) + link(#0070f3), 상태색 error/warning/cyan/violet.
- 적용 방법: `globals.css`의 `@theme`에서 Tailwind의 slate/gray/red/amber/green/sky/blue/purple 색 이름을 DESIGN.md 색으로 고정하고, 둥글기(`rounded-2xl`=12px, `xl`=8px, `lg`=6px)와 글꼴(Geist / Geist Mono, `geist` 패키지)을 바꿔서 화면 파일을 하나하나 고치지 않고 전체가 따르게 했습니다. 표 머리글은 caption-mono, 제목은 display(600, 음수 자간).
- 시스템 설정의 대표 색 후보도 DESIGN.md 색(먹색·파랑·보라·청록·주황·빨강)만 있고, 진한 색·연한 색은 DESIGN.md의 짝(deep/soft)을 씁니다. 「직접 고르기」로 다른 색을 넣을 때만 계산해서 만듭니다.

## 화면 색과 메뉴 순서 바꾸기

- 「시스템 설정 → 화면 색과 메뉴 순서」에서 대표 색을 고르면 버튼·선택된 메뉴·강조 색이 한꺼번에 바뀝니다. 8가지 미리 만든 색 또는 직접 고르기.
- 같은 카드에서 메뉴를 ▲▼로 순서를 바꾸고, 안 쓰는 메뉴는 「표시」를 끄면 왼쪽 메뉴와 휴대폰 메뉴에서 숨겨집니다. (묶음 안에서 순서가 바뀌고, 관리자 메뉴는 고정)
- 저장하면 모든 직원 화면에 적용됩니다. 「기본으로」를 누르면 처음 상태로 돌아갑니다.
- 저장 위치: `data/settings.json` 의 `theme` · `menu`. 색은 `src/lib/theme.ts` 에서 진한 색·연한 색을 자동으로 만들어 `<html>` 의 CSS 변수(`--primary` 등)로 넣습니다.

## 서버에 올리기 (밖에서·휴대폰에서 쓰기)

월 1~2만 원짜리 클라우드 서버 한 대면 직원들이 어디서나 접속할 수 있습니다.
`deploy/README.md` 에 서버 만들기 → 도메인 연결 → 설치 → 백업까지 순서대로 적어 두었습니다.
휴대폰에서는 브라우저로 접속한 뒤 "홈 화면에 추가"를 누르면 앱처럼 쓸 수 있습니다.

- `Dockerfile`, `docker-compose.yml` – 앱 + HTTPS 웹서버(Caddy) + 매일 백업을 한 번에 실행
- `deploy/setup.sh` – 첫 설치, `deploy/update.sh` – 새 버전 반영, `deploy/restore.sh` – 백업 복구
- `.env.production.example` – 서버용 설정 예시

## 폴더 구조

- `src/app/login` – 로그인 화면과 로그인/로그아웃 처리, `src/proxy.ts` – 출입 검사
- `src/app/dashboard/*` – 각 메뉴 화면 (tasks 할일, schedule 일정, projects, customers, leads, quotes 견적, sales 매출, purchases 매입, payments 입금, mail 메일, resource-library 자료실, business-cards 명함)

- `src/app/dashboard/[...slug]` – 아직 안 만든 메뉴의 "준비 중" 화면
- `src/app/api/assistant` – AI 비서, `src/app/api/business-cards/scan` – 명함 사진 인식, `src/app/api/mail/*` – 메일 계정·조회·발송·기록, `src/app/api/data/[collection]` – 데이터 읽기/쓰기, `src/app/api/members` – 담당자 목록

- `src/lib/assistantContext.ts` – 회사 현황 요약, `src/lib/localAssistant.ts` – 내장 비서
- `src/components` – 사이드바, 휴대폰용 메뉴 서랍(MobileNav), 카드, 탭, 정렬 표 머리글, 담당자 필터, AI 비서 창 등 공통 부품
- `src/data/sample.ts` – 처음 실행 시 들어가는 예시 데이터, `src/data/menu.ts` – 메뉴 정의

세 파일 모두 브라우저에서 바로 열립니다.

**구조적 전제 3가지**

1. 시장의 크기 = 물류 반경. 운반비가 납품가의 15~30%이므로 반경 밖은 애초에 못 이긴다.
2. 승부는 견적 요청 전에 끝난다. 개입 시점은 설계 단계와 낙찰 직후.
3. KS 규격품은 제품으로 차별화가 안 된다. 실제 차별점은 납기·현장 대응·서류·혼적 배송.

**1인 운영일 때 달라지는 것**

- 제약은 돈이 아니라 **시간**. 모든 방법을 "투입 시간당 매출"로 평가.
- 마케팅을 별도 업무로 만들지 않는다. **출고·세금계산서·입고·회계마감·견적** 다섯 접점에 1~3분짜리 동작을 붙인다.
- 발은 남의 발을 쓴다. **대리점·운송기사·원자재 공급사 영업**이 영업 조직.
- 캐파가 상한이므로 "더 많은 주문"이 아니라 "더 좋은 주문". 안 받을 주문 기준을 먼저 정한다.
- 매출 공식: 거래처 수(대리점에 위임) × **거래처당 주문 횟수** × **주문당 금액**
