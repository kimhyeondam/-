# 현장 레이더 — 구현 보고

## 상태

**입찰공고 수집은 완성됐다. 낙찰(개찰결과) 연결만 남았다.**

`bid` 스펙은 문서를 옮겨 적은 것이 아니라 `probe.py` 로 실제 호출해서 확정했다.

```
base_url  http://apis.data.go.kr/1230000/ad/BidPublicInfoService
operation getBidPblancListInfoCnstwk   (inqryDiv=1)
```

`scsbid`(낙찰정보서비스)는 아직 되는 조합을 찾지 못했다. 그동안 낙찰시공사
열은 "개찰전"으로 채워진다. 나머지 기능은 전부 동작한다.

## 이 도구의 기준 — 관급자재금액

운영 주체가 관급자재 공급사이므로, 공사 규모가 아니라 **관급자재금액**이
선별과 우선순위의 기준이다.

- `관급자재금액` = `contrctrcnstrtnGovsplyMtrlAmt`(도급자 설치 관급자재)
  + `govcnstrtnGovsplyMtrlAmt`(관급공사 관급자재)
- `min_govsply_amt` 미만은 버린다. 기본 1원 = 관급자재가 잡힌 공고만 본다.
- 시트는 관급자재금액 내림차순으로 쌓인다. 그 순서가 곧 접촉 우선순위다.
- 공사 추정가격 하한(`min_amount`)은 기본으로 꺼 뒀다.

관급자재는 시공사가 아니라 발주처가 산다. 그래서 발주처 담당자 이름과
직통번호(`ntceInsttOfclNm`, `ntceInsttOfclTelNo`)를 시트에 함께 넣는다.

## 미확인 — 낙찰정보서비스

`api_spec.yaml` 의 `scsbid` 절이 아직 TODO다. `probe.py scsbid` 로
오퍼레이션 7종 x inqryDiv 3종을 두드렸으나 데이터를 받은 조합이 없었다.
실패 사유(resultMsg)를 보고 후보를 넓히거나, 문서의 오퍼레이션명을
확인해야 한다.

확인해야 할 문서:

| 서비스 | 문서 |
|---|---|
| 조달청_나라장터 입찰공고정보서비스 | https://www.data.go.kr/data/15129394/openapi.do |
| 조달청_나라장터 낙찰정보서비스 | https://www.data.go.kr/data/15129397/openapi.do |

두 URL은 검색 결과로 확인된 실제 데이터셋 페이지다. 각 페이지의
"요청 변수" / "출력 결과" 표에 적힌 이름을 그대로 옮기면 된다.

특히 확인이 필요한 것:

1. **엔드포인트 base URL과 공사 오퍼레이션명** — 나라장터 API는 개편 이력이 있어
   기억이나 블로그 글에 의존하면 안 된다. 문서의 "서비스 URL"을 그대로 쓸 것.
2. **지역 필터 수단** — 요청 파라미터로 지역을 걸 수 있는지, 아니면 응답을 받아서
   걸러야 하는지. 현재 구현은 **응답을 받아서 거르는 쪽**을 가정한다
   (발주처명·공고명에서 시·군명을 찾는다). 요청 단계 필터가 있으면 호출량이 줄어드니
   `bid.extra_params` 에 추가하면 된다.
3. **조회기간 상한** — 문서에 상한이 있으면 `bid.max_range_days` 를 그 값으로 바꿀 것.
4. **금액·개찰일시·상세URL 항목의 존재 여부** — 목록 오퍼레이션 응답에 없으면
   `fields` 에서 `null` 로 두면 된다. 그 열은 공란으로 나가고, 금액 필터는 자동으로 건너뛴다.

## 커버 범위 불확실 — 공기업 발주

LH·한국도로공사·한국수자원공사 발주가 나라장터에 얼마나 올라오는지,
각 기관 자체 전자조달 시스템에만 올라오는 공고가 있는지 **문서로 확인하지 못했다**
(위와 같은 차단 사유). 현재 구현은 나라장터 응답의 수요기관명에
`agency_keywords` 를 걸어 잡는 방식이고, 자체 시스템 전용 공고는 잡지 못한다.

첫 실전 실행 뒤, 알고 있는 해당 기관 발주 건이 시트에 나오는지 대조해서
누락이 크면 별도 소스를 붙여야 한다.

## 설계 판단 두 가지 (알려둘 것)

**1. 중복 판정 색인을 별도 파일로 뒀다.**
시트 열 구성이 12개로 고정이라 공고번호를 넣을 자리가 없다. 그래서 공고번호는
`data/_seen_bids.json` 에 따로 쌓는다. 이 파일이 지워져도 기존 CSV의
(현장명, 발주처, 공고일) 조합으로 대체 판정하므로 중복이 터지지는 않는다.

**2. 시·군 축약형을 함께 잡는다.**
검증 중에 실제로 걸린 문제다. 지자체 공고는 "김해시 진영읍…"이라 그대로 잡히는데,
LH 공고는 "김해 진례지구…"라 `김해시` 로는 안 걸린다. 그래서 접미사(시/군/구)를
뗀 축약형도 매칭하되, 뒤에 한글이 바로 붙으면 제외한다
(`고성군` → `고성` 이 `고성능` 에 걸리는 것을 막는다).

## 검증 결과

`bid` 는 실제 API 호출로 엔드포인트와 응답 항목명을 확정했다(최근 7일
totalCount 2,385건). 파이프라인은 실제 응답 필드명으로 만든 픽스처
(`fixtures/sample.json`, 6건)를 **진짜 `api_spec.yaml`** 로 돌려 확인했다.

| 항목 | 결과 |
|---|---|
| bid 엔드포인트 | 통과 — 실제 호출로 확정 |
| 관급자재 0원 공고 제외 | 통과 — 밀양 측구 건 제외 |
| 제외어 | 통과 — 전기공사 건 제외 |
| 지역 필터 | 통과 — 대구 북구 건 제외, 대상 밖 0행 |
| 현장 지역명 공란 시 되짚기 | 통과 — LH 김해 건을 공고명으로 포착 |
| 관급자재금액 합산 | 통과 — 도급자설치 3.1억 + 관급공사 0.2억 = 3.3억 |
| 정렬 | 통과 — 5.2억 / 3.3억 / 0.885억 순 |
| 품목 추정 | 통과 — 하수도→흄관·맨홀, 도로→경계블록·측구, 하천→옹벽블록 |
| 중복 미증가 | 통과 — 2회 실행 후 신규 0건, 3행 유지 |
| 엑셀 호환 | 통과 — UTF-8 BOM |
| 인증키 정규화 | 통과 — Encoding/Decoding/따옴표 모두 처리 |

**실제 수집 결과를 공고URL과 눈으로 대조하는 검증은 아직 못 했다.**
첫 실전 실행 때 상위 3건을 열어 확인해야 한다.
