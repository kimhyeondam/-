# 현장 레이더 — 구현 보고

## 상태

**완성. 공사·물품 두 레이더 모두 동작한다.**

스펙은 문서를 옮겨 적은 것이 아니라 `probe.py` 로 실제 호출해서 확정했다.
둘 다 같은 서비스 아래에 있다.

```
base_url  http://apis.data.go.kr/1230000/ad/BidPublicInfoService
공사      getBidPblancListInfoCnstwk   (inqryDiv=1, 7일 2,385건)
물품      getBidPblancListInfoThng     (inqryDiv=1, 7일 2,686건)
```

## 두 개의 레이더

| | 무엇을 잡나 | 실행 |
|---|---|---|
| 공사 레이더 | 이 현장에 관급자재가 얼마나 잡혔나 — 착공 전 선행 신호 | `run.py` |
| 물품 레이더 | 우리 품목이 실제로 발주됐나 — 입찰·납품 기회 | `run_goods.py` |

관급자재는 발주처가 물품으로 따로 발주한다. 공사 공고의 관급자재금액은
"여기에 물량이 잡혔다"는 예고이고, 실제 기회는 그 뒤 물품 공고로 나온다.
설정 파일도 따로다(`config.yaml` / `goods_config.yaml`).

물품 쪽은 공사현장 지역명이 없어 수요기관명으로만 지역을 가르고,
선별 1차 관문이 금액이 아니라 **품목 키워드**다.

## 이 도구의 기준 — 관급자재금액

운영 주체가 관급자재 공급사이므로, 공사 규모가 아니라 **관급자재금액**이
선별과 우선순위의 기준이다.

- `관급자재금액` = `contrctrcnstrtnGovsplyMtrlAmt`(도급자 설치 관급자재)
  + `govcnstrtnGovsplyMtrlAmt`(관급공사 관급자재)
- `min_govsply_amt` 미만은 버린다. 기본 1원 = 관급자재가 잡힌 공고만 본다.
- 시트는 관급자재금액 내림차순으로 쌓인다. 그 순서가 곧 접촉 우선순위다.
- 공사 추정가격 하한(`min_amount`)은 기본으로 꺼 뒀다.

관급자재는 시공사가 아니라 발주처가 산다. 그래서 발주처 담당자 이름과
직통번호(`ntceInsttOfclNm`, `ntceInsttOfclTelNo`)를 시트에 함께 넣는다.

## 검증된 것

2026-08-31 실제 수집(전남·광주, 최근 7일, 117건)에서 사용자가 상위 건의
공고URL을 열어 **관급자재금액이 나라장터 원문과 일치함을 확인했다.**
광주 자치구도 통합 표기(`전남광주통합특별시 북구`)로 정상 수집된다.

## 설계 판단 두 가지 (알려둘 것)

**1. 중복 판정 색인을 별도 파일로 뒀다.**
시트 열 구성이 12개로 고정이라 공고번호를 넣을 자리가 없다. 그래서 공고번호는
`data/_seen_bids.json` 에 따로 쌓는다. 이 파일이 지워져도 기존 CSV의
(현장명, 발주처, 공고일) 조합으로 대체 판정하므로 중복이 터지지는 않는다.

**2. 시·군 축약형을 함께 잡는다.**
검증 중에 실제로 걸린 문제다. 지자체 공고는 "김해시 진영읍…"이라 그대로 잡히는데,
LH 공고는 "김해 진례지구…"라 `김해시` 로는 안 걸린다. 그래서 접미사(시/군/구)를
뗀 축약형도 매칭하되, 뒤에 한글이 바로 붙으면 제외한다
(`고성군` → `고성` 이 `고성능` 에 걸리는 것을 막는다).

## 검증 결과

`bid` 는 실제 API 호출로 엔드포인트와 응답 항목명을 확정했다(최근 7일
totalCount 2,385건). 파이프라인은 실제 응답 필드명으로 만든 픽스처
(`fixtures/sample.json`, 6건)를 **진짜 `api_spec.yaml`** 로 돌려 확인했다.

| 항목 | 결과 |
|---|---|
| bid 엔드포인트 | 통과 — 실제 호출로 확정 |
| 관급자재금액 원문 대조 | 통과 — 실제 공고 원문과 일치 (사용자 확인) |
| 지정 발주처 포함 | 통과 — 전남개발공사 건은 현장 지역명이 비어도 담고, 경기주택도시공사는 제외 |
| 같은 현장 병합 | 통과 — 재공고 3건이 최신 1건으로 접힘 |
| 관급자재 0원 공고 제외 | 통과 — 밀양 측구 건 제외 |
| 제외어 | 통과 — 전기공사 건 제외 |
| 지역 필터 | 통과 — 대구 북구 건 제외, 대상 밖 0행 |
| 현장 지역명 공란 시 되짚기 | 통과 — LH 김해 건을 공고명으로 포착 |
| 관급자재금액 합산 | 통과 — 도급자설치 3.1억 + 관급공사 0.2억 = 3.3억 |
| 정렬 | 통과 — 5.2억 / 3.3억 / 0.885억 순 |
| 품목 추정 | 통과 — 하수도→흄관·맨홀, 도로→경계블록·측구, 하천→옹벽블록 |
| 중복 미증가 | 통과 — 2회 실행 후 신규 0건, 3행 유지 |
| 엑셀 호환 | 통과 — UTF-8 BOM |
| 인증키 정규화 | 통과 — Encoding/Decoding/따옴표 모두 처리 |

시트 열은 관급자재 영업에 실제로 쓰는 것만 남겼다. 발주처담당자·담당자연락처·
개찰일·낙찰시공사·시공사연락처는 뺐고, 그에 따라 낙찰정보서비스(scsbid)
연동도 제거했다. 다시 필요해지면 `probe.py` 로 오퍼레이션을 찾아 붙인다.
