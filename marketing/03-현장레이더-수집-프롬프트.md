# 현장 레이더 자동 수집 프롬프트

`marketing/01-수주전략.html`의 **레버 1 — 착공 전 현장 레이더**를 자동화하기 위한 프롬프트다.
매주 월요일 손으로 하던 "반경 내 신규 낙찰·착공 현장 스캔"을 스크립트로 대체한다.

- **대상 도구**: Claude Code (파일 생성·명령 실행 권한이 있는 에이전트)
- **수집 범위**: 나라장터 관급 공사 입찰공고·개찰결과 + LH·한국도로공사·한국수자원공사 등 공기업 발주
- **산출물**: 시·군별 신규 발주 현장 CSV (엑셀에서 바로 열림)

## 붙여넣기 전 준비 (1회, 약 10분)

1. [공공데이터포털](https://www.data.go.kr)에서 **조달청_나라장터 입찰공고정보**, **조달청_나라장터 낙찰정보** 두 서비스에 활용신청 (일반 인증키는 보통 즉시 승인)
2. 발급된 인증키를 환경변수로 설정: `export G2B_SERVICE_KEY=발급받은키`
3. 아래 프롬프트에서 대괄호 항목(`[기준 시·군 목록]`, `[최소 공사금액]`)을 실제 값으로 바꾼다

> 이 프롬프트는 파일을 만들고 명령을 실행하는 에이전트용이다.
> 붙여넣기 전에 scope lock(`tools/site_radar/`, `data/`), 금지 항목, 정지 조건이 실제 프로젝트 구조와 맞는지 확인할 것.

## 프롬프트

````
<context>
콘크리트 2차제품(흄관·맨홀·측구·경계블록·옹벽블록) 제조사의 영업용 "현장 레이더"를 자동화한다.
수주는 견적 요청 전, 즉 낙찰 직후~착공 전에 결정된다. 따라서 공장 물류 반경 안의 신규 관급 공사 발주를 매주 자동으로 긁어와야 한다.
현재 저장소 상태: marketing/ 아래 전략 문서만 있고 수집 코드는 없다.
</context>

<task>
아래 사양대로 시·군 단위 신규 발주 공고를 수집하는 Python 스크립트를 tools/site_radar/ 에 새로 만든다.
</task>

<data_sources>
1. 공공데이터포털(data.go.kr) — 조달청 나라장터 입찰공고정보 서비스 (공사 입찰공고)
2. 공공데이터포털 — 조달청 나라장터 낙찰정보 서비스 (개찰결과·낙찰 시공사)

착수 전에 WebFetch로 위 두 서비스의 현재 공식 문서를 열어 다음을 확인하고, 확인된 값만 코드에 쓴다:
- 정확한 엔드포인트 base URL과 오퍼레이션명
- 필수 요청 파라미터(조회기간, 페이지, 응답형식)
- 지역제한/수요기관 지역 관련 파라미터의 존재 여부와 이름
- 응답 필드명

문서에서 확인되지 않은 파라미터명·필드명은 추측해서 쓰지 않는다. 확인 불가 항목은 REPORT.md "미확인" 절에 적고 나에게 묻는다.
LH·한국도로공사·한국수자원공사 발주는 상당수가 나라장터에 게시되므로 수요기관명 필터로 함께 잡는다. 다만 각 기관 자체 조달시스템에만 올라오는 공고가 있는지 문서로 확인하고, 그 범위를 REPORT.md에 명시한다. 확인되지 않으면 "커버 범위 불확실"로 적는다.
</data_sources>

<config>
tools/site_radar/config.yaml 로 분리한다:
- target_regions: [기준 시·군 목록 — 예: 김해시, 창원시, 밀양시]
- agency_keywords: [시청, 군청, 도청, 한국토지주택공사, LH, 한국도로공사, 한국수자원공사]
- lookback_days: 7
- min_amount: [최소 공사금액, 원]
- exclude_keywords: [전기, 통신, 소방, 정보화, 조경식재, 용역, 유지관리용역]
- item_rules: 공고명 키워드 → 예상 품목 매핑
    하수도/우수관/배수 → 흄관·맨홀
    도로 확포장/도로개설 → 경계블록·측구·집수정
    하천/사면/옹벽 → 옹벽블록·호안블록

인증키는 환경변수 G2B_SERVICE_KEY 에서만 읽는다. 키 값을 코드·config·로그·커밋에 절대 남기지 않는다.
</config>

<output>
실행: `python tools/site_radar/run.py`
결과: data/radar_YYYY-MM-DD.csv (UTF-8 BOM, 엑셀에서 바로 열림)

열 순서 고정:
공고일 | 지역(시군) | 현장명 | 발주처 | 공사종류 | 추정금액 | 개찰(예정)일 | 낙찰시공사 | 시공사연락처 | 예상소요품목 | 공고URL | 접촉상태

- 기존 CSV가 있으면 공고번호 기준으로 중복을 제거하고 신규 행만 추가한다.
- 낙찰시공사는 낙찰정보 API로 채우고, 미개찰이면 "개찰전"으로 적는다.
- 예상소요품목은 config의 item_rules로만 산출한다. 규칙에 걸리지 않으면 공란.
- 접촉상태는 항상 공란(사람이 채우는 열).
- 각 단계 완료마다 stdout에 `✅ [완료 항목]` 한 줄을 출력한다.
- 마지막에 요약을 출력한다: 총 수집 건수 / 시군별 건수 / 신규 건수 / API 실패 건수.
</output>

<constraints>
- 표준 라이브러리 + requests + PyYAML 만 사용한다. 다른 의존성이 필요하면 설치 전에 나에게 묻는다.
- tools/site_radar/ 와 data/ 밖의 파일은 수정하지 않는다. marketing/ 기존 문서와 README.md는 건드리지 않는다.
- API 호출은 초당 1회 이하로 제한한다. 429/5xx는 지수 백오프(2s, 4s, 8s)로 최대 3회 재시도한다.
- API가 돌려준 값만 기록한다. 금액·시공사·연락처를 추정으로 채우지 않는다. 값이 없으면 공란으로 둔다.
- 요청한 것만 만든다. 웹 대시보드, DB, 스케줄러, 알림 연동, 추가 리팩터링은 만들지 않는다.
</constraints>

<verification>
코드를 다 쓴 뒤 실제로 실행해서 아래 4개를 확인하고, 실행 출력과 함께 보고한다:
1. target_regions에 시·군 2곳, lookback_days 7로 실제 API를 호출해 성공 응답을 받는다.
2. 생성된 CSV의 첫 3행을 출력하고, 각 행의 공고URL을 WebFetch로 열어 현장명·발주처·금액이 일치하는지 대조한다.
3. 같은 명령을 두 번 실행해 중복 행이 늘지 않음을 보인다.
4. 지역 필터가 실제로 동작하는지 — target_regions 밖 지역 행이 0건임을 보인다.

실행하지 않은 것을 했다고 쓰지 않는다. 실패하면 실패한 그대로 보고한다.
</verification>

<stop_conditions>
다음 상황에서는 즉시 멈추고 나에게 묻는다:
- G2B_SERVICE_KEY가 없거나 활용신청 승인 대기 상태다
- 공식 문서에서 필요한 오퍼레이션이나 지역 필터 수단을 찾지 못했다
- 새 의존성 설치, 파일 삭제, tools/ 와 data/ 밖 파일 수정이 필요하다
</stop_conditions>
````

## 스크립트가 만들어진 뒤

- 주 1회 자동 실행이 필요하면 cron 한 줄로 붙인다: `0 8 * * 1 cd /경로 && python tools/site_radar/run.py`
- CSV의 `접촉상태` 열은 비워둔 채 나온다. 전략 문서의 **D+3 접촉 규칙**대로 사람이 채운다.
- 민간 착공현장(세움터)과 지자체 고시·공고는 이 스크립트 범위 밖이다. 필요해지면 별도 소스로 추가한다.
